第一部分 · 认识系统

01 · 全景与核心概念

在钻进任何一行代码之前,先建立三样东西:这个系统要解决什么问题、它的核心心智模型、以及它的代码分层与仓库布局。这三样东西会在后面每一章被反复引用。

本章要点

  • Hindsight 不是"把对话历史塞进向量库",而是把文本加工成一张原子事实网络(事实 + 实体 + 三种边),再在其上做检索与推理。
  • 记忆分三类:world facts / experience facts / mental models(observations);前两者由 Retain 写入,第三者由后台巩固生成。
  • 对外只有三个操作:Retain(写)、Recall(读)、Reflect(推理)。
  • 代码分三层:API 适配 → Engine 门面 → 流水线包;读的时候绝不要跨层找东西,也绝不要整文件读那两个"巨石文件"。
  • 全课的复杂度几乎都源自三组工程张力,先记住它们。

1. 从"Agent 需要记忆"说起

大语言模型本身是"无状态"的:每次调用,它只看得见你这次传进去的上下文窗口。要让一个 Agent 跨会话"记得"用户、"学到"经验,最朴素的做法有两种:

  • 朴素 RAG:把原文切成块(chunk)→ 向量化 → 查询时做相似度检索,把最像的几段塞回 prompt。
  • 知识图谱(KG):把信息抽成"实体—关系"的图,查询时做图遍历。

这两种都有明显短板。朴素 RAG 检索的是"哪段原文像这句话",但 Agent 真正想要的是"我学到了什么、这件事和谁有关、何时发生、我后来的信念怎么变了"——原文块里这些信号是散的、隐含的,相似度检索抓不住"时间""因果""同一实体的不同说法"。知识图谱结构好,但建图昂贵、难维护,且单独用会丢掉文本里的细微语义。

📖 Hindsight 的取舍

把两者的长处合并,再加一层"学习":写入时用 LLM 把文本抽成原子事实并建好结构(像 KG),检索时多路并行、向量 + 关键词 + 图 + 时间一起上(比 RAG 强),事后再把零散事实巩固成更高层的观察(这是 RAG/KG 都没有的"学习"能力)。官方把这叫"仿人记忆"(biomimetic):像人一样,既有对世界的认知、又有亲身经历、还能反思总结。

一句话记住整个系统的设计出发点:

💡 全课的叙事主线

Hindsight 不是"存原文再 embed",而是把文本变成一张"可检索、可链接、可巩固"的原子事实网络。写入(Retain)负责把这张网建出来,检索(Recall)负责在网上高效地找到相关的点,反思(Reflect)负责在网点之上做推理,巩固(Consolidation)负责把网点提炼成更高层的"观察"。后面所有的复杂度,都是在为这张网的"写得对、找得到、能学习"服务。

2. 核心心智模型:记忆长什么样

Hindsight 把记忆组织成三个层次,越往上越"抽象"、越接近"知识":

'这个客户对价格敏感'"] end subgraph l2["② 结构化:实体 + 三种边"] E["实体归一
Alice ≡ alice ≡ 爱丽丝"] LK["时序边 · 语义边 · 因果边"] end subgraph l1["① 原子事实(memory_units)"] WF["World facts
'炉子会变热'"] EF["Experience facts
'我碰了炉子,很疼'"] end l1 --> l2 --> l3 l3 -. 巩固(后台 LLM 合成) .- l1
图 1-1:记忆的三个层次。底层是原子事实,中层是结构化(实体与边),顶层是巩固出的观察。巩固是自底向上的"学习"。
  • ① 原子事实(facts):一条可以独立成立的断言。分两种——world fact(关于世界的客观知识,如"Alice 在 Google 当工程师")和 experience fact(Agent 的亲身经历,如"我上次部署忘了跑迁移,出事了")。数据库里它们都是 memory_units 表的一行,用 fact_type 区分。事实是系统统一的语义基元——这一点非常关键,后面会反复出现。
  • ② 实体与边:每条事实里提到的实体(人、地点、组织、甚至"友谊""职业成长"这类抽象概念)会被抽取并归一——"Google""google inc""谷歌"指向同一个规范实体。事实之间还会建三种边:时序边(时间上接近)、语义边(向量上相近)、因果边(这件事实由那件引起)。这些边是图检索的"米"。
  • ③ 观察 / 心智模型(observations / mental models):从零散事实里反思、合成出来的更高层判断,如"用户偏好函数式编程"。它本身也存成一种特殊的事实(fact_type='observation'),带"有多少条证据支撑"(proof_count)和"由哪些事实合成"(source_memory_ids)。

⚠️ 先分清两个最容易混的词

代码里 observation(观察) 和 mental model(心智模型) 是两个不同的东西,源码注释专门强调过:
· observation = 由巩固引擎自底向上、自动从原始事实合成,存在 memory_units 表(fact_type='observation')。
· mental model = 用户自定义的"我想长期跟踪的某个主题",存在单独的 mental_models 表,本质是"被固化下来的 reflect 结果",按需刷新。
口语里它们常被混用,但读代码时必须分清。第 09、10 章会展开。

3. 三个对外操作

系统对使用者只暴露三个动词。把它们和上面的记忆层次对应起来看:

操作做什么读/写用到哪些记忆层
Retain(记住)把输入文本交给 LLM,抽出事实、时间、实体、关系,规范化后落库写生产 ①② 层;并为 ③ 层埋好钩子(observation_scopes)
Recall(想起)并行跑语义 / 关键词 / 图 / 时间四路检索,融合 + 重排 + 按 token 裁剪读消费 ①②③ 层(observation 也可被当作一种事实检索)
Reflect(反思)跑一个带工具的 agent 循环,按需检索,生成一段"带性格"的、有据可依的回答读(不写)消费 ③ 层(mental model / observation)+ ① 层(兜底原始事实)

还有一个不在三个动词里、但贯穿始终的后台过程:Consolidation(巩固)。它在 Retain 之后异步运行,把新事实合成/更新成 observation。之所以不放进 Retain 里顺手做,是因为 Retain 是"流式按块提交"的,进行的途中根本没有"全文事实全集"可供综合——这个"为什么"第 09 章会细讲。

✅ 一个能帮你建立直觉的类比

把 Hindsight 想象成一个勤快的助理的笔记本:Retain 是"听你说话后,把要点一条条记下来,并标清楚谁、何时、因为什么"(不是录音笔式地存原文);Recall 是"你问问题时,他同时用‘关键词目录’‘相似话题’‘人物关系’‘时间线’四种方式翻笔记,再把最相关的几条递给你";Reflect 是"你问他‘你对我有什么了解’,他翻一翻自己总结过的印象,再结合原始笔记,认真回答";Consolidation 是"他每晚把白天零散的笔记整理成几条长期印象"。

6. bank 与 disposition:隔离与性格

两个贯穿全课的业务概念:

  • bank(记忆库):一个完全隔离的记忆存储,相当于"某个用户/Agent 的一个大脑"。每个请求只针对一个 bank;bank 之间严格不串数据(数据库层用 schema / bank_id 双重隔离)。跨 bank 查询是客户端的责任,系统不提供。
  • disposition(性格):每个 bank 可配三个 1–5 的整数特质——skepticism(怀疑度)、literalism(字面度)、empathy(共情度)。它只影响 Reflect 的语气与判断,完全不影响 Recall。实现上它只是被序列化进 system prompt 的一行 skepticism=3, literalism=3, empathy=3,具体怎么影响回答交给模型自己体会(第 10 章会看到,这是一种很"软"的机制,和强约束的 directive 形成鲜明对比)。

7. 贯穿全课的三组工程张力

最后,也是本章最重要的一节。这个系统看起来"过度复杂"的地方,几乎都能追溯到三组张力。把它们记牢,后面每遇到一个费解的设计,你大概率能对号入座:

张力直白说工程对策(后续章节)
LLM 慢且贵 ↔ 写入要快、可恢复 抽事实要调 LLM,又慢又花钱;但用户不能等,失败了还不能整篇作废。 streaming 小批提交、delta 增量(只重抽变化部分)、异步入队 + 幂等(第 03、04 章)
检索需要预计算结构 ↔ 结构计算可能失败 图/时间检索要依赖写入时建好的边;但建边(ANN、实体解析)是可能失败的慢操作。 Phase1 读外 / Phase2 短事务原子写 / Phase3 提交后补边(第 05 章)
并发多租户 ↔ 文档级一致性 很多请求同时写同一个 bank、甚至同一个文档;但不能写出重复或互相覆盖。 content_hash 去重、SELECT … FOR UPDATE 行锁、同文档顺序切片(第 03 章)

✅ 怎么用这三组张力

后面每当你在源码注释里看到 #1875、#2662、#1888 这样的 issue 编号,基本就是某组张力在现实中"咬过人"留下的疤。读这些注释,比读函数体更快理解"为什么要这么写"。本课会在相关处引用这些 issue 编号。

小结

  • Hindsight 的核心命题:把文本加工成原子事实网络(事实 + 归一实体 + 时序/语义/因果边),而非存原文块。
  • 记忆三层:world/experience facts → 实体与边 → 巩固出的 observations;另有用户自定义的 mental models(别混淆)。
  • 三个操作 Retain / Recall / Reflect,加一个后台的 Consolidation。
  • 代码三层 API → Engine 门面 → 流水线包,按层阅读、按函数跳转,远离两个巨石文件的通读。
  • 三组张力(慢贵↔快恢复、预计算↔会失败、并发↔一致性)是理解全部复杂度的钥匙。
