Part 4 · Reasoning & Consolidation

10 · Reflect: Disposition-Aware Reasoning

Recall is “pure retrieval”: give a query, get facts back. Reflect is “reasoning”: it runs a tool-using agent loop that decides for itself what to fetch and how deep, then synthesizes a grounded, disposition-aware answer. This chapter dissects that loop, its tools, the division of labor between mental models and observations, and the contrast between the “soft” mechanism disposition and the “hard” mechanism directive.

Chapter takeaways

  • Reflect is read-only: it writes no data, producing one markdown answer.
  • It's a native tool-calling loop (not ReAct text-parsing), default 10 turns, scaled by budget to 5/10/20.
  • Context is lazy-loaded: the initial prompt holds only the bank identity + directives + the mental-model count; memories are fetched by tools on demand, so the prompt doesn't grow with the bank.
  • Retrieval is hierarchical: mental model (human-curated) > observation (auto-consolidated) > recall (raw-fact fallback), and it forces one ordered pass first, then hands control to the model.
  • Disposition is soft (one k=v line the model interprets); directive is hard (MANDATORY, injected start and end, done must report compliance). Don't conflate them.

💡 Why not stuff the memories into the prompt up front?

The source comment is blunt: “mental models are NOT preloaded to keep the initial prompt small … critical for banks with many mental models.” If you stuffed a bank's entire observations/models into the prompt at the start, the bigger the bank the more the prompt explodes. Instead it's lazy-loaded: only the bank identity, directives, and a COUNT(*) go in (the count decides whether to expose the “search mental models” tool). So the initial prompt is O(1), independent of bank size; the agent fetches memories with tools as needed.

2. The agent loop

Locate: engine/reflect/agent.py → _run_reflect_agent_inner.

It's a native tool-calling loop (OpenAI-format tools + tool_choice, via llm_config.call_with_tools), with tool calls returned as structured result.tool_calls — not the ReAct style of having the model emit text that you then parse. Which LLM? The bank-resolved reflect config (any provider). Termination conditions (any one ends the loop):

  • The model calls the done() tool with an answer;
  • After having already called a tool, the model returns no tool call → treated as a legitimate stop, running one clean forced synthesis; (if it never called a tool, that's the transport-not-supporting-tools case → raise ReflectToolCallError);
  • Reached the last turn (is_last) → tools removed, forced text;
  • Proactive context-budget guard: accumulated messages exceed max_context_tokens → forced synthesis;
  • Context overflow / unrecoverable LLM error → forced synthesis from gathered evidence.

Max iterations default 10, but reflect_async scales by budget: base × {LOW:0.5, MID:1.0, HIGH:2.0} → effectively 5/10/20.

📖 Key design: force the hierarchical retrieval first, then let go

The first few turns don't use auto. The loop forces the model to call in order “mental models → observations → recall” (only for the enabled tools), and only after that hands back auto:

engine/reflect/agent.py · _run_reflect_agent_inner (excerpt)python
# Force the full hierarchical retrieval path (only for enabled tools),
# then allow auto.
forced_sequence = []
if has_mental_models:    forced_sequence.append("search_mental_models")
if include_observations: forced_sequence.append("search_observations")
if include_recall:       forced_sequence.append("recall")

if iteration < len(forced_sequence):
    iter_tool_choice = LLMToolChoice.named(forced_sequence[iteration])
else:
    iter_tool_choice = LLM_TOOL_CHOICE_AUTO

result = await llm_config.call_with_tools(
    messages=messages, tools=tools, scope="reflect_tool_call",
    tool_choice=iter_tool_choice)

Multiple tool calls in one turn execute in parallel via asyncio.gather. There's also an optimization: if the forced mental-model result is “fresh and usable”, it releases to auto early, short-circuiting the lower layers.

3. The tools: four hierarchical + done

Locate: schemas in reflect/tools_schema.py, implementations in reflect/tools.py, dispatch in agent.py:_execute_tool.

The module docstring states the philosophy: “a hierarchical retrieval strategy: ① search_mental_models (human-curated, highest quality) → ② search_observations (auto-consolidated, freshness-aware) → ③ recall (raw facts, ground-truth fallback).”

ToolPurpose
search_mental_modelsSemantic search over the mental_models table; returns content + is_stale. Only exposed when the bank has any
search_observationsSearch auto-consolidated observations (fact_type='observation'), returning freshness; if stale, prompts “also use recall to verify”
recallRaw facts (world+experience) fallback; used when no model/observation exists, they're stale, or detail is needed
expandBy memory_ids fetch more context (memory → chunk → document); not exposed when document-text storage is off
doneGive the final markdown answer + supporting IDs; with directives, also requires directive_compliance

✅ The “structured refresh” of a mental model

When refreshing a mental model, the system does not let the model rewrite the whole prose (that would “drift”); instead it has the model emit a set of structured operations (append_block, replace_section_blocks, …) applied to a StructuredDocument. Untouched sections are then copied through verbatim — “prose drift becomes structurally impossible”. reflect/structured_doc.py + delta_ops.py do this (the write path, not reflect's read path).

5. Disposition (soft) vs directive (hard)

Locate: reflect/prompts.py.

The injection of disposition is strikingly plain: three 1–5 integers serialized into one line in the system prompt, with no “if skepticism ≥ 4 then do X” logic at all — entirely left to the model to interpret:

engine/reflect/prompts.py · build_system_prompt_for_tools (excerpt)python
parts.append(f"## Memory Bank: {name}")
if mission: parts.append(f"Mission: {mission}")
disposition = bank_profile.get("disposition", {})
if disposition:
    traits = [f"{k}={disposition[k]}" for k in ("skepticism","literalism","empathy") if k in disposition]
    if traits: parts.append(f"Disposition: {', '.join(traits)}")
# renders as: ## Memory Bank: Alice / Mission: ... / Disposition: skepticism=3, literalism=3, empathy=3

Whereas a directive is a completely different, strong mechanism: its own table, injected as “hard rules” at both the start and end of the system prompt (recency effect), and structurally enforced in the done tool:

engine/reflect/prompts.py · build_directives_section (excerpt)python
parts = ["## DIRECTIVES (MANDATORY)",
         "These are hard rules you MUST follow in ALL responses:", ""]
for rule in rules: parts.append(f"- {rule}")
parts += ["", "NEVER violate these directives, even if other context suggests otherwise.",
          "IMPORTANT: Do NOT explain or justify how you handled directives ..."]

⚠️ A key distinction when teaching

Disposition is soft: one k=v line the model freely interprets; beyond the 1–5 range there's no validation at all — the same values may behave differently across models. Directive is hard: a MANDATORY section, start+end placement, done requiring directive_compliance, violations “rejected”. In one line: disposition nudges tone and reasoning; directive constrains output. And directives must be re-injected in the final-synthesis separate LLM call (that call can't see the agent prompt), else weak models quietly drift back to the default language.

6. Design decisions & gotchas

Decision / gotchaNotes
Why an agent loop, not one-shotReflect must choose and decompose retrieval; the prompt even teaches “don't echo the user's question, decompose it into targeted searches”. A one-shot prompt can't adapt its second search to what the first returned
Evidence before doneIf it calls done with no retrieved IDs, a fake tool result rejects it: “you must search first”
Native tool calling, fail loudWhen the transport doesn't support tools, raise — rather than “salvage the untooled text”, which risks surfacing raw tool-call JSON as the answer
Anti-hallucinated tools / citationsCalls to unenabled tools are rejected; done's answer text is taken verbatim, but the IDs are validated against what was actually retrieved (unretrieved IDs dropped)
Budget changes three things at onceIteration multiplier (5/10/20) + a “research depth” prompt section (shallow/moderate/deep) + whether fresh mental models short-circuit
Non-conversationalThe prompt forbids follow-up questions / “would you like me to…”, because “the user cannot reply”
Temporal semantics by prompt, not code“latest mentioned_at wins” and a 6-step conflict-resolution scaffold live entirely in the prompt; results are sorted by semantic relevance, not time, and the prompt warns the model not to treat position as recency

Summary

  • Reflect = a read-only tool-calling agent loop; context lazy-loaded (initial prompt O(1)); hierarchical retrieval (MM > observation > recall), forced first then released.
  • Tools mostly reuse recall (different fact_type filter); expand fetches context; done wraps up and validates citations.
  • Mental model = user-pinned result (mental_models table); observation = auto-consolidated (fact_type='observation', evidence with exact quotes).
  • Disposition soft (one k=v line), directive hard (MANDATORY + compliance report) — don't conflate.
