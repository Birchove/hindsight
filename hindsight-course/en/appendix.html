✅ The three most important reading disciplines

① Read per layer: API adapter → Engine facade → pipeline packages; don't hunt across layers. ② Jump by function: the two enormously long files (memory_engine.py ~14k lines, api/http.py ~7.5k lines) are never read top to bottom. ③ Line numbers drift: always locate by “file path + function name”; the code snippets here are excerpted for explanation.

E. Run & debug quick reference

shellbash
# 1) prepare config
cp .env.example .env        # fill LLM provider/key; with no key set HINDSIGHT_API_LLM_PROVIDER=none

# 2) start the service (repo scripts auto-read .env)
./scripts/dev/start.sh          # API + console UI
./scripts/dev/start-api.sh      # API only

# 3) or Docker (bundles embedded pg0)
docker run -it -p 8888:8888 -p 9999:9999 \
  -e HINDSIGHT_API_LLM_API_KEY=$OPENAI_API_KEY \
  -v hindsight-data:/home/hindsight/.pg0 ghcr.io/vectorize-io/hindsight:latest

# 4) or Python embedded (no server)
pip install hindsight-all -U

# API: http://localhost:8888   UI: http://localhost:9999

Common env vars (see .env.example and chapter 11): HINDSIGHT_API_LLM_PROVIDER (openai/anthropic/gemini/groq/ollama/lmstudio/minimax/none), HINDSIGHT_API_LLM_API_KEY, HINDSIGHT_API_LLM_MODEL, HINDSIGHT_API_EMBEDDINGS_PROVIDER (local/tei), HINDSIGHT_API_RERANKER_PROVIDER (local/tei), HINDSIGHT_API_DATABASE_URL (unset → embedded pg0).

✅ Debugging tips

· Single-step: use the process started by start-api.sh (or run hindsight_api.main straight from your IDE); breakpoint the orchestrator functions (e.g. _streaming_retain_batch, _search_with_retries).
· No cost: set provider=none (chunks mode, consolidation off), or run tests with MockLLM (deterministic, canned by scope). Reading the code itself needs no key.
· See the SQL: the real SQL is in engine/db/ops_postgresql.py; pair with EXPLAIN to understand partial-index hits.

F. Reading the tests

Test directory hindsight-api-slim/tests/, two kinds:

  • Deterministic tests (the majority): use MockLLM and pure functions, assert directly. Reading these builds “expected behavior” fastest: test_delta_retain.py, test_retain_append_mode.py, test_async_batch_retain.py, test_async_retain_operation_id.py, test_retain_same_document_concurrency.py, test_retain_transient_extraction_failure.py.
  • LLM-behavior tests: when what's under test is “how the model interprets a prompt”, MockLLM can't simulate it and exact asserts flake across providers. So use a real LLM + LLM-as-judge: mark pytestmark = pytest.mark.hs_llm_core, run the real pipeline, then judge with tests/llm_judge.assert_meets_criteria (the judge model is independent of the provider under test, default Gemini). Structural deterministic facts (counts, field presence, a substring injected into a prompt) stay as direct asserts in fast unit tests.
shellbash
cd hindsight-api-slim
uv run pytest tests/ -n auto                 # all tests, parallel
uv run pytest tests/test_retain.py::test_retain_simple -v   # one test
uv run ruff check . && uv run ruff format .  # lint/format
uv run ty check hindsight_api/               # very fast type checker
./scripts/hooks/lint.sh                       # repo-wide lint (run after Python/TS changes)
