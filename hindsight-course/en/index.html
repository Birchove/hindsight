What this course is

The folder you have is a fork of Hindsight, an open-source agent long-term memory system: it gives LLM agents the ability to remember, recall, and reflect, so an agent doesn't just “run with its conversation history” but actually learns over time. It reports state-of-the-art results on long-term-memory benchmarks like LongMemEval, and it is used in production.

The system is mature, which also means it is large: several core-engine files run to tens of thousands of lines, and the monorepo also contains a Next.js console, a Rust CLI, dozens of framework integrations, and multi-language SDKs. Dropping straight into the source is a good way to get lost.

So this is not a “list of functions.” It breaks the system into progressive chapters; each one first asks what problem it solves, then how it solves it, then walks the key logic against the source, and finally flags the pitfalls. Where the system implements the same thing several ways (a dozen LLM providers, several document parsers, etc.), we read the most representative one in depth and cover the rest by comparison.

📖 The narrative thread

In one line: Hindsight does not “store the raw text and embed it” — it turns text into an atomic fact network that is retrievable, linkable, and consolidable. Almost all the complexity is in service of making that network “correct to write, efficient to query, and able to learn.” Keep that thread in mind and everything clicks into place.

Hindsight in one minute

Hindsight organizes an agent's memory in a “biomimetic” way, in three tiers:

  • World facts: objective statements about the world, e.g. “the stove gets hot”, “Alice works at Google”.
  • Experience facts: the agent's own experiences, e.g. “I touched the stove and it hurt”.
  • Mental models / observations: higher-level understanding reflected and consolidated out of the scattered facts, e.g. “the user prefers functional programming”.

Memories live in isolated banks — think “one brain per user/agent” — with strict no-leakage between banks. Each bank can also carry a disposition (skepticism, literalism, empathy, each 1–5); it only affects how reflect reasons, never recall.

Fig 0-1: all three operations revolve around one memory bank. Retain writes structured memory, Recall retrieves, Reflect reasons; consolidation is the background loop that distills facts into observations.
  • Retain hands the input to an LLM that extracts facts, time, entities and relations, normalizes them, and stores them — the write path.
  • Recall runs semantic / keyword (BM25) / graph / temporal retrieval in parallel, then fuses, reranks, and trims to a token budget — the read path.
  • Reflect runs a tool-using agent loop that retrieves memories and mental models on demand and produces a grounded, disposition-aware answer.

Run the system (strongly recommended)

The best companion to reading source is an instance you can run and breakpoint. Hindsight ships an embedded database (pg0), so it starts with no external dependencies. The easiest path is Docker:

shell · from the READMEbash
export OPENAI_API_KEY=sk-xxx

docker run -it --pull always --name hindsight --restart unless-stopped \
  -p 8888:8888 -p 9999:9999 \
  -e HINDSIGHT_API_LLM_API_KEY=$OPENAI_API_KEY \
  -v hindsight-data:/home/hindsight/.pg0 \
  ghcr.io/vectorize-io/hindsight:latest

# API: http://localhost:8888   Console UI: http://localhost:9999

Then exercise the three operations with the official Python client and feel “input → memory → retrieval → reflection” first-hand:

quickstart.pypython
from hindsight_client import Hindsight

client = Hindsight(base_url="http://localhost:8888")

# Retain: hand information to the system (it extracts facts, entities, relations)
client.retain(bank_id="my-bank",
              content="Alice works at Google as a software engineer")

# Recall: retrieve memories (4-way parallel + fusion + rerank)
client.recall(bank_id="my-bank", query="What does Alice do?")

# Reflect: produce a grounded, disposition-aware answer
client.reflect(bank_id="my-bank", query="Tell me about Alice")

Want to single-step through the source? The repo has local dev scripts under scripts/dev/: ./scripts/dev/start.sh starts the API and the Next.js console together; ./scripts/dev/start-api.sh starts only the API (it reads .env automatically). Copy .env.example to .env and fill in your LLM provider and key. Most tests use a MockLLM and run offline:

shellbash
cd hindsight-api-slim && uv run pytest tests/ -n auto   # all tests, parallel
cd hindsight-api-slim && uv run pytest tests/test_retain.py::test_retain_simple -v  # one test

✅ No LLM key? You can still read

Set HINDSIGHT_API_LLM_PROVIDER to none and the system forces a degraded “whole-chunk-as-a-memory-unit, no LLM extraction” path (covered in chapter 11). Tests use the built-in MockLLM — fully deterministic, no cost. So reading the code itself never needs a key.
