第四部分 · 推理与巩固

10 · Reflect:带性格的推理

Recall 是"纯检索":给查询、还事实。Reflect 是"推理":它跑一个带工具的 agent 循环,自己决定去查什么、查多深,再综合成一段带性格、有据可依的回答。这一章拆解这个循环、它的工具、mental model 与 observation 的分工,以及 disposition 这个"软"机制和 directive 这个"硬"机制的对比。

本章要点

  • Reflect 是只读的:不写任何数据,产出一段 markdown 回答。
  • 它是一个原生 tool-calling 循环(不是 ReAct 文本解析),默认 10 轮、按预算缩放成 5/10/20。
  • 上下文懒加载:初始 prompt 只放 bank 身份 + directive + mental model 数量;记忆靠工具现查,避免 prompt 随 bank 膨胀。
  • 检索是分层的:mental model(人工精选)> observation(自动巩固)> recall(原始事实兜底),且先强制按序查一遍,再交给模型自由发挥。
  • disposition 是软的(一行 k=v 交给模型体会);directive 是硬的(MANDATORY、首尾注入、done 要交代合规)。别混。

💡 为什么不把记忆预先塞进 prompt?

源码注释很直白:"心智模型不预载,以保持初始 prompt 小巧……对于心智模型很多的 bank,这点至关重要。"如果一上来就把一个 bank 的全部观察/模型塞进 prompt,bank 越大 prompt 越炸。改成懒加载:只放 bank 身份、directive、和一个 COUNT(*)(决定要不要暴露"查心智模型"这个工具)。于是初始 prompt 是 O(1) 的,与 bank 大小无关;记忆由 agent 用工具按需取。

2. agent 循环

定位:engine/reflect/agent.py → _run_reflect_agent_inner。

它是原生 tool-calling 循环(OpenAI 格式的 tools + tool_choice,经 llm_config.call_with_tools),工具调用以结构化 result.tool_calls 返回——不是让模型输出文本再去解析的 ReAct 风格。用哪个 LLM?bank 解析出的 reflect 配置(任意 provider)。终止条件(满足任一即止):

  • 模型调 done() 工具给出答案;
  • 模型在已经调过工具之后不再调工具 → 视为正常收尾,跑一次干净的强制综合;(若从没调过工具,那是传输层不支持工具 → 抛 ReflectToolCallError);
  • 到了最后一轮(is_last)→ 撤掉工具,强制出文本;
  • 主动的上下文预算守卫:累计消息超 max_context_tokens → 强制综合;
  • 上下文溢出/不可恢复的 LLM 错误 → 用已收集证据强制综合。

最大轮数默认 10,但 reflect_async 按预算缩放:base × {LOW:0.5, MID:1.0, HIGH:2.0} → 实际 5/10/20。

📖 关键设计:先强制分层检索,再放开

前几轮不用 auto。循环会按"心智模型 → 观察 → recall"的顺序强制模型依次调用(只对已启用的工具),之后才交回 auto:

engine/reflect/agent.py · _run_reflect_agent_inner(节选)python
# 强制走完分层检索路径(只对启用的工具),之后才允许 auto。
forced_sequence = []
if has_mental_models:   forced_sequence.append("search_mental_models")
if include_observations: forced_sequence.append("search_observations")
if include_recall:       forced_sequence.append("recall")

if iteration < len(forced_sequence):
    iter_tool_choice = LLMToolChoice.named(forced_sequence[iteration])
else:
    iter_tool_choice = LLM_TOOL_CHOICE_AUTO

result = await llm_config.call_with_tools(
    messages=messages, tools=tools, scope="reflect_tool_call",
    tool_choice=iter_tool_choice)

同一轮里的多个工具调用用 asyncio.gather 并行执行。还有个优化:若强制查到的心智模型"新鲜可用",就提前放开到 auto,短路掉更低层。

3. 工具:分层的四类 + done

定位:schema 在 reflect/tools_schema.py,实现在 reflect/tools.py,分发在 agent.py:_execute_tool。

模块 docstring 说明了哲学:"分层检索:① search_mental_models(人工精选,最高质量)→ ② search_observations(自动巩固,带新鲜度)→ ③ recall(原始事实,真相兜底)。"

工具作用
search_mental_models在 mental_models 表上做语义检索;返回内容 + is_stale。仅当 bank 有才暴露
search_observations检索自动巩固的观察(fact_type='observation'),返回新鲜度;若陈旧,提示"再用 recall 核实"
recall原始事实(world+experience)兜底;无模型/观察、或它们陈旧、或需要细节时用
expand按 memory_ids 取更多上下文(memory → chunk → document);禁用文档正文存储时不暴露
done给出最终 markdown 答案 + 支撑 ID;有 directive 时还要必填 directive_compliance

4. mental model 与 observation:具体区别

mental modelobservation
来源用户定义的主题(自顶向下)巩固引擎自动合成(自底向上)
存储mental_models 表(名字/内容/embedding/trigger…)memory_units 里 fact_type='observation'
本质"被固化的 reflect 结果",按需刷新带 title/content/evidence(每条证据必须有逐字 quote)
趋势有 is_stale(刷新后是否有新记忆)由证据时间戳算法算出 Trend(STABLE/STRENGTHENING/WEAKENING/NEW/STALE),不经 LLM

✅ mental model 的"结构化刷新"

刷新一个 mental model 时,系统不让模型重写全文(那会"漂移"),而是让它输出一组结构化操作(append_block、replace_section_blocks…)作用在一个 StructuredDocument 上。这样没被碰到的段落是逐字拷贝过去的——"散文漂移在结构上不可能发生"。reflect/structured_doc.py + delta_ops.py 就是干这个的(写路径,不是 reflect 的读路径)。

5. disposition(软)vs directive(硬)

定位:reflect/prompts.py。

disposition 的注入朴素得惊人:三个 1–5 的整数,直接序列化成一行放进 system prompt,没有任何"若怀疑度≥4 就如何"的逻辑,全交给模型自己体会:

engine/reflect/prompts.py · build_system_prompt_for_tools(节选)python
parts.append(f"## Memory Bank: {name}")
if mission: parts.append(f"Mission: {mission}")
disposition = bank_profile.get("disposition", {})
if disposition:
    traits = [f"{k}={disposition[k]}" for k in ("skepticism","literalism","empathy") if k in disposition]
    if traits: parts.append(f"Disposition: {', '.join(traits)}")
# 渲染成:## Memory Bank: Alice / Mission: … / Disposition: skepticism=3, literalism=3, empathy=3

而 directive 是完全不同的强机制:独立成表、作为"硬规则"在 system prompt 的开头和结尾都注入(利用近因效应),还在 done 工具里结构化强制:

engine/reflect/prompts.py · build_directives_section(节选)python
parts = ["## DIRECTIVES (MANDATORY)",
         "These are hard rules you MUST follow in ALL responses:", ""]
for rule in rules: parts.append(f"- {rule}")
parts += ["", "NEVER violate these directives, even if other context suggests otherwise.",
          "IMPORTANT: Do NOT explain or justify how you handled directives ..."]

⚠️ 教学时的关键区分

disposition 是软的:一行 k=v,模型自由解读,除了 1–5 范围没有任何校验——同样的值在不同模型上行为可能不同。directive 是硬的:MANDATORY 段、首尾注入、done 必填 directive_compliance、违反会"被拒"。一句话:disposition 调节语气与判断,directive 约束输出。而且 directive 在最终综合那次单独的 LLM 调用里要再注入一遍(那次调用看不见 agent prompt),否则弱模型会悄悄漂回默认语言。

6. 设计决策与易踩坑

决策 / 坑说明
为什么用 agent 循环而非一次性reflect 要选择并分解检索;prompt 还专门教"别照抄用户问题,要分解成有针对性的搜索"。一次性 prompt 无法根据第一次的结果调整第二次
证据先于 done若没检索到任何 ID 就想 done,会被一个假工具结果打回:"你必须先搜索"
原生工具调用,失败要响亮传输层不支持工具时直接抛错,而不是"抢救那段无工具文本"——以免把原始工具调用 JSON 当答案吐出去
防幻觉工具 / 防幻觉引用调未启用的工具会被拒;done 的答案文本照单全收,但 ID 会和"真正检索到的"校验(没检索到的 ID 被丢弃)
预算一次改三样轮数倍数(5/10/20)+ prompt 里的"研究深度"段(浅/中/深)+ 是否允许新鲜心智模型短路
非对话式prompt 禁止反问/"还要我…吗",因为"用户无法回复"
时间语义靠 prompt 而非代码"最新 mentioned_at 优先"、冲突解决六步法都写在 prompt 里;检索结果按语义相关排,不按时间,还警告模型别把位置当新旧

小结

  • Reflect = 只读的 tool-calling agent 循环;上下文懒加载(初始 prompt O(1));分层检索(MM > observation > recall)先强制后放开。
  • 工具大多复用 recall(过滤不同 fact_type);expand 取上下文;done 收尾并校验引用。
  • mental model = 用户固化结果(mental_models 表);observation = 自动巩固(fact_type='observation',证据带逐字 quote)。
  • disposition 软(一行 k=v)、directive 硬(MANDATORY + 合规交代),别混。
