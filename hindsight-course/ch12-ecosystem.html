第六部分 · 生态概览

12 · 生态全景

前 11 章都在 hindsight-api-slim/ 里。这一章跳出来,鸟瞰整个 monorepo:系统怎么被打包、被部署、被集成进各种框架,控制台和 CLI 长什么样,基准怎么跑。这一章不逐行读代码,而是建立"这个项目作为一个产品长什么样"的地图——并对你说的"其余实现方式,对比介绍即可"做个交代。

本章要点

  • 同一个引擎有三种交付形态:独立服务器(Docker)、Python 嵌入(hindsight-all,自带 pg0)、npm 嵌入(hindsight-all-npm)。
  • 客户端有 4 种语言 SDK(Python/TS/Rust/Go),都从 OpenAPI 生成;CLI 是 Rust;还有"两行代码"的 LLM Wrapper。
  • 49 个框架集成大多是同一个模式的变体:把 retain/recall/reflect 包进框架的"记忆/工具"接口。
  • control plane 是 Next.js 管理 UI,代理调用 dataplane;加 API 参数时两边要同步改。
  • 存储默认内嵌 pg0,也支持外部 PostgreSQL 与 Oracle 23ai(功能对等);migration 用方言分发。

1. 三种"跑起来"的形态

引擎只有一份,但交付形态有三种,适配不同场景:

形态包数据库适合
独立服务器Docker 镜像(docker/standalone、docker/docker-compose)内嵌 pg0,或外挂 PostgreSQL生产、多客户端共享
Python 嵌入hindsight-all(Intel Mac 用 hindsight-all-slim)内嵌 pg0,无需外部依赖本地开发、单机、脚本里直接用
npm 嵌入hindsight-all-npm内嵌Node/TS 项目里直接用

📖 pg0:让"零依赖"成为可能的内嵌 Postgres

Hindsight 离不开 PostgreSQL + pgvector。为了不让用户先装一个数据库,它把 PostgreSQL 内嵌成 pg0(数据放在 ~/.pg0)。所以 docker run 一条命令、或 pip install hindsight-all 之后,数据库是自动起来的。这也是为什么 pg0.py、daemon.py 这些文件存在。第 02 章讲的"每个租户一个 schema"的多租户,在这之上照样成立。

README 里"最简集成"其实是 LLM Wrapper:把你现有的 LLM 客户端换成 Hindsight 的包装器,之后每次 LLM 调用会自动存取记忆,号称两行代码。若需要更细的控制,才用 SDK/HTTP 直接调三个操作。

2. 客户端、SDK 与 CLI

  • SDK:hindsight-clients/ 下有 Python、TypeScript、Rust、Go 四种。它们是生成的——改了 API 后跑 ./scripts/generate-openapi.sh 重新生成 OpenAPI 规格,再跑 ./scripts/generate-clients.sh 重生成全部 SDK。所以别手改生成的客户端。
  • CLI:hindsight-cli/ 是 Rust 写的(自称 "A beautiful CLI for Hindsight"),用 progenitor 从 OpenAPI 生成 API 客户端。
  • 嵌入式 CLI:hindsight-embed/ 提供"无需服务器的本地记忆操作"。

✅ 一条贯穿全仓库的纪律:先改 API,再重生成

API 是"单一事实来源"。改 dataplane 端点后:① 重生成 OpenAPI 规格(CI 会校验)→ ② 重生成 SDK → ③ 同步改 control plane 的代理路由与类型。这条链条解释了为什么仓库里那么多东西是"生成的"——为了让四种语言 + CLI + UI 永远和 API 对齐。

3. 集成生态:49 个,一个模式

hindsight-integrations/ 下有 49 个框架集成:LangGraph、CrewAI、Pydantic AI、AutoGen/AG2、Claude Code、Cursor、Cline、LlamaIndex、Haystack、n8n、Dify……数量吓人,但绝大多数是同一个模式的变体:

📖 怎么读这 49 个(不用都读)

挑一个你熟悉的框架的集成读透(比如你用过 LangGraph 就读 langgraph/,用过 Claude Code 就读 claude-code/),搞清它"在哪个钩子、把什么、翻译成哪个操作"。其余的扫一眼 README 即可——差异主要在"框架的挂载点叫什么、消息结构长什么样",而不是 Hindsight 这边。

仓库对"新增集成"有硬性清单(来自 CLAUDE.md,正好说明一个"完整集成"包含什么):

  1. 必须有测试——要模拟/驱动外部系统(mock 框架接口,验证集成确实正确调用了 Hindsight);纯 helper 单测不算。
  2. CI job——在 .github/workflows/test.yml 按现有模式加(构建、装依赖、uv run pytest tests -v),并接入 detect-changes 只在文件变化时跑。
  3. 发布——把集成名加进 scripts/release-integration.sh 的 VALID_INTEGRATIONS。
  4. 遵守代码规范——Python 风格、类型安全、结构化数据不用裸 dict、不多项 tuple 返回。

4. 控制台(Control Plane)

hindsight-control-plane/ 是一个 Next.js 管理 UI(页面有 dashboard / banks / login 等),默认跑在 9999 端口。它自己不存数据,而是代理调用 dataplane API。它的 API 路由几乎和 dataplane 一一对应:

control plane 路由(src/app/api/)对应
recall / reflect / memories(retain)三大操作
banks / profile / statsbank 管理与统计
documents / chunks / entities / graph记忆内容浏览与可视化
operations / extract / files / health / version运维与工具

⚠️ 加 API 参数,记得两边同步

CLAUDE.md 专门强调:在 dataplane 加/改参数时,control plane 要同步改三处——① 路由处理器(从 body 解构出参数、传给 SDK 调用)、② 客户端类型(src/lib/api.ts 里 recall()/reflect()/retain() 的类型)、③ 用到它的 UI 组件。漏一处,UI 上就用不了新参数。

5. 存储与部署

  • 默认内嵌 pg0,零依赖;生产可换外部 PostgreSQL(docker/docker-compose)。
  • Oracle 23ai 也支持,且"功能对等"。这解释了代码里大量的方言分发:每个 migration 通过 run_for_dialect(pg=..., oracle=...) 选择 _pg_upgrade 或 _oracle_upgrade(第 02 章那些"Oracle 没有 unnest、observation 用连接表"的差异就是这么来的)。有个 pytest lint(test_migration_shape.py)会在 migration 漏掉分发器时挂 CI。
  • 向量后端可插拔(pgvector/diskann/vchord/scann,第 02 章)、全文后端可插拔(原生 tsvector / pg_search / pgroonga / vchord,第 07 章)。
  • 编排:helm/(K8s)、monitoring/(监控);配置模板是 .env.example(setup 脚本会拷成 .env)。

6. 基准与可观测性

hindsight-dev/ 与 scripts/benchmarks/ 提供:

基准测什么脚本
LongMemEval长期记忆的准确率(Hindsight 宣称 SOTA)run-longmemeval.sh
LoCoMo另一套准确率基准run-locomo.sh
性能系统吞吐/延迟(mock LLM + pg0,--scale tiny 做冒烟)run-perf-test.sh
巩固consolidation 的表现run-consolidation.sh

结果可以用 start-visualizer.sh 在 localhost:8001 看。可观测性方面,引擎内置 metrics.py(Prometheus 风格)、tracing.py、llm_trace.py(记录每次 LLM 调用,第 11 章的 usage stash 就喂给它)。

7. 配置体系回顾

把所有配置知识收个尾(详见第 11 章):配置是层级的——全局(env)→ 租户(经扩展)→ bank(数据库)。字段分两类:

  • 可配置(hierarchical):能被租户/bank 覆盖——LLM 行为设置、retain 模式、chunk 大小、mission、disposition、recall 预算等。
  • 静态(server 级):数据库 URL、端口、全局并发上限、以及(注意)LLM provider/model/key。

加一个新配置字段的标准流程(来自 CLAUDE.md):在 config.py 加 ENV_*/DEFAULT_*/dataclass 字段,可配就加进 _CONFIGURABLE_FIELDS;引擎里用 ConfigResolver.get_bank_config 按 bank 解析;文档与 .env.example 同步;.env.example 改完还要拷一份到 hindsight-embed/(有个同步测试盯着)。

小结

  • 一份引擎,三种交付:Docker 服务器 / Python 嵌入 / npm 嵌入;pg0 让零依赖成为可能。
  • 4 种 SDK + Rust CLI 都从 OpenAPI 生成;改 API 要走"重生成 + 同步 control plane"的链条。
  • 49 个集成 = 一个模式的 49 个变体;读透一个、扫其余;新增集成有硬性清单。
  • control plane 是代理型 Next.js UI;存储默认 pg0,可换 PG/Oracle(方言分发)。
  • 基准分准确率(LongMemEval/LoCoMo)与性能两类;配置层级化、字段分可配/静态。
