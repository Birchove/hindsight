C. 易混概念速查

容易混澄清
retain_async vs retain_batch_async前者是单条薄封装,逻辑在后者
extract_facts_from_contents vs ..._batch_api后者是供应商 Batch API 路径,配置启用才走
types.ExtractedFact vs fact_extraction 里的 Pydantic 模型管道对象 vs LLM schema,不同层
两个 generate_embeddings_batchembedding_processing(包装)vs embedding_utils(实现)
document_tags vs item tags前者 deprecated,用 item 级 tags
同步切批 vs 异步 child 切批_split_contents_into_sub_batches vs _split_contents_into_async_children,约束不同
fact_type world/assistant vs world/experience抽取 prompt 用前者,落库映射成后者(第 04 章)
observation vs mental model自动巩固的事实行 vs 用户固化的 reflect 结果(独立表)(第 01、09、10 章)
disposition vs directive软(一行 k=v)vs 硬(MANDATORY + 合规交代)(第 10 章)
LLMConfig不是配置对象,就是 LLMProvider 的别名(第 11 章)
"层级 LLM 配置"provider/model/key 实为服务器级 + 按操作,非 per-bank(第 11 章)

E. 本地运行与调试速查

shellbash
# 1) 准备配置
cp .env.example .env        # 填 LLM provider/key;无 key 可设 HINDSIGHT_API_LLM_PROVIDER=none

# 2) 起服务(仓库脚本,自动读 .env)
./scripts/dev/start.sh          # API + 控制台 UI
./scripts/dev/start-api.sh      # 只起 API

# 3) 或 Docker(自带内嵌 pg0)
docker run -it -p 8888:8888 -p 9999:9999 \
  -e HINDSIGHT_API_LLM_API_KEY=$OPENAI_API_KEY \
  -v hindsight-data:/home/hindsight/.pg0 ghcr.io/vectorize-io/hindsight:latest

# 4) 或 Python 嵌入(无需服务器)
pip install hindsight-all -U

# API: http://localhost:8888   UI: http://localhost:9999

常用环境变量(详见 .env.example 与第 11 章):HINDSIGHT_API_LLM_PROVIDER(openai/anthropic/gemini/groq/ollama/lmstudio/minimax/none)、HINDSIGHT_API_LLM_API_KEY、HINDSIGHT_API_LLM_MODEL、HINDSIGHT_API_EMBEDDINGS_PROVIDER(local/tei)、HINDSIGHT_API_RERANKER_PROVIDER(local/tei)、HINDSIGHT_API_DATABASE_URL(不设则用内嵌 pg0)。

✅ 调试建议

· 想单步:用 start-api.sh 起的进程(或直接在 IDE 里跑 hindsight_api.main),在编排器函数(如 _streaming_retain_batch、_search_with_retries)打断点。
· 不想花钱:设 provider=none(走 chunks 模式、关巩固),或跑测试用 MockLLM(确定性、按 scope 返回罐头)。读代码本身不需要任何 key。
· 看 SQL:真实 SQL 在 engine/db/ops_postgresql.py,配合 EXPLAIN 理解偏索引命中。

F. 测试导读

测试目录 hindsight-api-slim/tests/,分两类:

  • 确定性测试(大多数):用 MockLLM、纯函数,直接 assert。读这些最快建立"预期行为":test_delta_retain.py、test_retain_append_mode.py、test_async_batch_retain.py、test_async_retain_operation_id.py、test_retain_same_document_concurrency.py、test_retain_transient_extraction_failure.py。
  • LLM 行为测试:验证"模型如何解读 prompt"时,MockLLM 模拟不了,精确断言又会跨 provider 抖动。于是用真 LLM + LLM-as-judge:标 pytestmark = pytest.mark.hs_llm_core,跑真管线,再用 tests/llm_judge.assert_meets_criteria 判定(判官模型独立于被测 provider,默认 Gemini)。结构性的确定事实(计数、字段存在、某子串被注入 prompt)仍用快速单测直接 assert。
shellbash
cd hindsight-api-slim
uv run pytest tests/ -n auto                 # 并行跑全部
uv run pytest tests/test_retain.py::test_retain_simple -v   # 跑单个
uv run ruff check . && uv run ruff format .  # lint/格式化
uv run ty check hindsight_api/               # 极快的类型检查
./scripts/hooks/lint.sh                       # 仓库统一 lint(改完 Python/TS 必跑)

G. 术语表

术语含义
bank一个隔离的记忆库("某个用户/Agent 的大脑"),bank 间不串数据
dispositionbank 的性格三特质(skepticism/literalism/empathy,1–5),只影响 reflect
memory_unit一条原子事实(数据库中心表的一行)
fact_typeworld(世界)/experience(经历)/observation(巩固出的观察)
chunk文档切块;主键确定性 {bank}_{doc}_{index}
entity / canonical_name归一后的实体;规范名先到先得、大小写不敏感
unit_entities事实↔实体的连接表
memory_links事实间的有类型带权边
temporal/semantic/causal三种边:时间接近 / 向量相近 / 因果(只写 caused_by)
observation巩固自底向上合成的观察(fact_type='observation')
mental model用户定义、按需刷新的固化 reflect 结果(mental_models 表)
proof_count / source_memory_idsobservation 的证据数 / 证据事实 ID 集
observation_scopes巩固粒度:combined/per_tag/all_combinations/shared/自定义
consolidation后台巩固:facts → observations 的"学习"
RRF倒数排名融合,Σ1/(60+rank),只用排名
bi-encoder / cross-encoder双塔(分别编码,便宜)/ 交叉(拼接精排,贵)
HNSW / pgvector近似最近邻索引 / Postgres 的向量扩展
delta retain增量写入:只重抽变化的块(乐观读 + 事务内复核)
streaming mini-batch按小批"抽取→建边→提交→释放",抗 OOM、可恢复
Phase1/2/3事务外慢读 / 短事务原子写 / 提交后补边
thinking_budgetrecall 的 top-k/节点预算(LOW100/MID300/HIGH~1000)
directivereflect 的硬规则(MANDATORY)
narrator抽取时注入的"第一人称是谁"提示
pg0内嵌 PostgreSQL,实现零依赖
TEIHuggingFace Text Embeddings Inference(远程 embedding/rerank)
